# Architecture

The native Qt Quick/QML UI talks to a QObject bridge. The bridge runs source discovery off the GUI thread and presents snapshots of durable state. SQLite WAL transactions serialize task claims. A scheduler owns one download slot plus independent Deepgram and OpenCode worker pools. Each worker has at most one active job and a private cancellation event.

Modules:

- `config.py`: validated non-secret settings, atomic writes, Windows credential-store integration, one-time worker-pool migration and explicit legacy import.
- `store.py`: tasks, stages, events and metadata cache; atomic claims and crash recovery.
- `services.py`: serialized YouTube access, speech normalization, Deepgram response/chunk persistence, isolated OpenCode execution, DOCX validation.
- `scheduler.py`: dependency/order gates, per-project concurrency, downstream queue/disk backpressure and worker lifecycle.
- `library.py`: type-grouped mirror of finished artifacts with a stable name manifest.
- `bridge.py`: UI operations and background discovery; no paid requests on startup.
- `models.py`: `DictListModel`, a QAbstractListModel over dicts that syncs rows in place (dataChanged / row insert / row remove) instead of the wholesale QVariantList republishing that used to reset every QML ListView to the top. Each model exposes a reserved `row` role holding the whole row dict; delegates read `row.<key>` so a data key (a worker's own `model` field) can never shadow the delegate's `model` wrapper.
- `qml/`: native screens and reusable controls. Data lists bind to bridge models (`jobsModel`, `workersModel`, `sourceModel`, `resultsModel`, `filesModel`, `providersModel`) so progress ticks, log lines and worker elapsed seconds update rows in place and never disturb the scroll position. Fonts and control metrics scale through `ui_scale` (0.8–1.4, live-applied from Settings) via a shared `fs()` helper and a `uiScale` property on the button/field primitives; `ui_compact` shrinks list rows, paddings and gaps through the `rh()`/`rs()`/`density` helpers; `ui_rail_collapsed` persists the collapsible navigation rail.

Task stage states: pending → running → completed. Terminal/action states: failed, blocked, uncertain, cancelled. Paused is used for local operations interrupted by process exit. Skipped stages count as dependency-satisfied only for valid plans. Claims compare-and-set `pending` under a database lock so two workers cannot execute the same stage. A transient failure returns a stage to pending with a future `next_retry` (deferral); the claim predicate honors that timestamp, so scheduled retries survive restarts and resume without user action. `retries` counts consecutive automatic deferrals of the current episode and resets on any explicit transition, success, or manual retry.

Service availability is split from job state: `manual_paused_stages` is set only by the user's pause button, while `automatic_stage_blocks` records an automatic guard (rejected cookies, low disk space) with its reason; `tick()` honours both, but only a user action lifts the manual one, while `Bridge.retry()`/`recheckStage()` lift the automatic one and requeue the jobs it parked — never the user's pause and never the rate-limit cooldown. The download worker row surfaces the automatic block reason through its error slot plus a `cooldownSeconds` countdown.

Automatic retry policy by `(stage, kind)`: YouTube download errors are classified by `Youtube.classify()` into `rate_limited` (429 — persists a shared cooldown into the `runtime_state` table so it survives restarts, defers the job to after the cooldown honoring `Retry-After` when present, budget `youtube_retry_attempts`), `failed` (network/server errors and anything unrecognised — escalating 5/15/45 minute deferrals, budget `youtube_retry_attempts`), `blocked` (cookies/login/age/403 — terminal for the job plus an automatic download-stage block), and `permanent` (deleted/private/geo/copyright/404 — one terminal failure with no retry and no service-wide stop). OpenCode `failed` outcomes keep the `auto_retry_attempts` budget, and its subscription-quota stops are classified from the provider's streamed error event (HTTP 429 / "usage limit has been reached"), not the exit code, and defer hourly up to `opencode_limit_retries` before a terminal failure that names the likely weekly limit. Paid Deepgram stages are never deferred at stage level; their transient handling stays in-request with `Retry-After`, and `uncertain` always requires a user decision.

The `runtime_state` table (key/value JSON in the same SQLite database) holds operational state that must survive a process restart, currently the YouTube cooldown deadline; it is read when the Youtube service is constructed and cleared lazily once expired, so a restart can never burst fresh requests while a persisted cooldown is still running.

Settings are snapshotted at enqueue. Worker model/language/agent parameters follow that snapshot; repaired credentials and executable/cookie paths apply to waiting jobs. Pool membership and worker enabled state apply immediately to future dispatch. Explicit reprocessing creates a new revision fingerprint and retains prior artifacts. Prompt templates are ordinary validated settings (`opencode_templates`): the selected template's text and name are snapshotted into the job's prompt at enqueue, so the revision fingerprint distinguishes templates and later template edits never rewrite queued jobs.

OpenCode workers carry a provider: `login` uses the credentials OpenCode already holds and its shared data directories, while every key-based provider (built-in OpenRouter, OpenAI API, Anthropic or Google, or a provider the user defines with its own environment variable) is fed a per-worker credential named `worker:provider` from the OS store and runs with `XDG_DATA_HOME`/`XDG_STATE_HOME` pointed at its own directory under `opencode_data_root`. That keeps five parallel runs off OpenCode's shared SQLite database and off the login directory, and auto-update is disabled for those runs so they cannot race over one binary. The model id is composed as `provider/model` unless it already carries the prefix; `login` models pass through as typed. An empty `variant` drops `--variant` entirely, because reasoning effort is provider specific. A key-based worker without a stored credential is parked with an explicit message instead of consuming a job. A session-only queue override can force one provider, model and reasoning level on every OpenCode worker regardless of its own configuration; it is not persisted, is refused for unknown providers, applies to the next dispatch, and an empty forced model falls back to the worker's own model composed with the forced provider — so the worker list and the dispatch always agree on what will run. The provider catalog is code-level for the built-ins plus `opencode_providers` for user-defined ones; a provider in use cannot be deleted.

A one-time migration normalises the pools: it removes the OpenRouter workers an earlier release created automatically (matched by id, provider and name together, so a hand-made worker is never touched) and tops both pools up to five workers by cloning the first saved worker, preserving the settings already in use. A worker the user deletes afterwards is never resurrected.

The library mirrors finished artifacts into `Word`, `التفريغات` and `الصوت` folders under `library_root`. A manifest pins the file name chosen for each (job, kind) pair, so republishing updates one file, two lessons sharing a title never overwrite each other, and a regenerated artifact refreshes its own mirror. Publishing copies (never moves) after each completed stage, is idempotent by size and timestamp, is skipped when `library_auto` is off, and can never fail a stage. Deletion is confined to the three library folders.

The bridge can arm a session-only auto-stop: when no stage is pending or running, no worker is active, and no discovery is in flight, it logs queue completion and quits through the normal shutdown path. Deferred, paused, blocked, or otherwise pending work always keeps the application open.

Deepgram commits raw responses before parsing and before honoring cancellation. Chunk responses are individually durable; a manifest marks completed audio segmentation. Lost network responses are uncertain rather than blindly retried. This reduces duplicate billing but cannot provide exactly-once external execution.

OpenCode works in a separate directory per task revision that receives a copy of the transcript; the prompt carries that copy's path plus the exact target DOCX path. The original TXT stays outside the agent's reach, and its hash is still verified after the run. Success requires process exit success, a valid editable DOCX, and an unchanged original hash. This is isolation of working files, not an OS security sandbox; OpenCode retains the account permissions granted by its own configuration, and a rejected external-directory permission is reported as a dedicated failure.

Known product limits are documented in README_AR.md. Native integration and scheduler tests use temporary directories and service doubles; external provider availability and actual formatting require live acceptance testing.
