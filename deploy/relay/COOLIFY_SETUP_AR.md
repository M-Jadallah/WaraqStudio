# إعداد ورق على Coolify الخاص بك

الإعداد المطلوب: **Coolify v4.4.6**، والدومين **waraqstudio.jadallah.work**، وعدة أشخاص مع **هاتف واحد لكل جهاز**. هذه خطوات تنفذها أنت؛ لم يُنشر التطبيق على الخادم بعد. تعتمد أسماء الحقول أدناه على توثيق Coolify الحالي؛ لم تُجرّب لوحة v4.4.6 الفعلية في هذه الجلسة.

## 1. اختر مصدر Git للمرة الأولى

استخدم مستودع [WaraqStudio](https://github.com/M-Jadallah/WaraqStudio) نفسه بعد وصول التغييرات إليه، وامنح Coolify صلاحية قراءته وحدد الفرع أو الالتزام المطلوب. هذا المستودع يبني تطبيق Windows بواسطة GitHub Actions وينشر بوابة الهاتف بواسطة Compose، كما يشرح [الدليل الرئيسي](../../README.md)؛ مسارا التشغيل مستقلان.

البديل: نزّل `WaraqGateway-Coolify.zip` من الإصدار المطلوب، وتحقق من `.zip.sha256` أو `SHA256SUMS`، ثم فك محتوياته إلى جذر مستودع Git خاص. حافظ على `relay/` و`deploy/` و`waraq/mobile/` و`.dockerignore` و`compose.relay.yaml` كما هي. لمعرفة المصدر الأصلي راجع الالتزام الكامل في ملف provenance لذلك الإصدار.

الحزمة تحتوي المصدر وDockerfile؛ ليست صورة حاوية جاهزة. اختر **Application من Git**، لا مجرد لصق Compose في مورد Empty؛ يحتاج البناء إلى بقية المصدر. لا تضع `.env` أو الأسرار في Git.

## 2. راجع DNS

اجعل سجل A للاسم `waraqstudio.jadallah.work` يشير إلى عنوان VPS المطلوب، وتحقق من قيمته الحالية لدى مزوّد DNS. لا تعتمد عنوانًا قديمًا في وثيقة أو سجل محلي. لا تضف AAAA إلا مع IPv6 عامل. اسمح بوصول 80 و443 إلى وكيل Coolify.

## 3. أنشئ التطبيق

داخل مشروعك في Coolify أضف تطبيقًا من مصدر Git، واختر Docker Compose. عيّن:

| الإعداد | القيمة |
|---|---|
| Base Directory | `/` |
| Docker Compose Location | `/compose.relay.yaml` |
| الخدمة العامة | `gateway` |
| المنفذ الداخلي | `8000` |
| الدومين العام | `https://waraqstudio.jadallah.work` |
| المسار | فارغ |

إذا كان حقل الدومين في لوحتك يجمع العنوان والمنفذ، أدخل **`https://waraqstudio.jadallah.work:8000`** فيه لتوجيه الوكيل إلى منفذ الحاوية؛ المستخدم يفتح الرابط العام **دون `:8000`**. هذه هي [طريقة Coolify لتحديد منفذ الحاوية](https://coolify.io/docs/applications/builds/docker-compose).

احفظ وحمّل Compose ثم اضبط دومين `gateway` فقط. لا تمنح `postgres` دومينًا أو منفذًا عامًا، ولا تختَر النشر Raw. أبقِ نسخة واحدة من `gateway` وعامل ASGI واحدًا.

## 4. راجع القيم التلقائية وانشر

في النشر الجديد، يولّد Coolify تلقائيًا `SERVICE_HEX_64_WARAQDB` ويحفظه للمورد. يستخدمه Compose نفسه لكلمة مرور PostgreSQL ورابط البوابة؛ **لا تكتب كلمة مرور أو `DATABASE_URL` يدويًا**، ولا تنسخ قالب `.env.example` إلى متغيرات Coolify. يبدأ `PUBLIC_BASE_URL` افتراضيًا بـ`https://waraqstudio.jadallah.work`، فغيّره فقط عند اختيار دومين آخر.

**عند ترقية قاعدة قديمة فقط:** قبل تحميل Compose الجديد، ضع `SERVICE_HEX_64_WARAQDB` بقيمة كلمة مرور القاعدة الحالية التي كان يحددها `POSTGRES_PASSWORD`. لا تسمح بتوليد سر جديد لقاعدة قائمة، ولا تحذف التخزين لمعالجة خطأ اتصال. [تفاصيل الترقية](README_AR.md#ترقية-مورد-قديم-له-قاعدة-موجودة).

اضغط Deploy. ينشئ التعريف الشبكة والتخزين وفحوص الصحة، وينتظر صحة PostgreSQL، ثم يهيئ مخطط القاعدة داخل مدخل `gateway` ويشغّل البوابة. توجد خدمتان فقط؛ التهيئة مرحلة داخل `gateway` وليست خدمة ثالثة. انتظر صحة الخدمتين وصلاحية شهادة HTTPS.

`PUBLIC_BASE_URL` لا يحتوي `:8000` أو مسارًا أو شرطة نهائية؛ `:8000` في إعداد دومين Coolify يحدد المنفذ الداخلي فقط.

للتحديث التلقائي لاحقًا، فعّل Auto deploy للمصدر المحدد واضبط تكامل Git أو webhook إذا كان مطلوبًا. هذا إعداد منصة أولي، منفصل عن ربط خدمات Compose التلقائي. نشر Coolify عند الدفع لا ينتظر GitHub Actions تلقائيًا؛ راجع نجاح اختبارات الالتزام أو انشر الالتزام المقبول يدويًا. [مرجع Coolify للنشر التلقائي](https://coolify.io/docs/applications/deployments/automatic-deployments).

## 5. افحص البوابة

افتح:

- [فحص الصحة](https://waraqstudio.jadallah.work/healthz): يجب أن يعيد `status: ok`.
- [واجهة الهاتف](https://waraqstudio.jadallah.work/internet): يجب أن تعرض واجهة ورق؛ الأجهزة تبقى محجوبة حتى الاقتران.

إذا فشل فحص الصحة الداخلي، نفذ من طرفية حاوية `gateway`:

```bash
python -m deploy.relay.healthcheck
```

## 6. سجل جهاز كل شخص واقرن هاتفه

من طرفية **gateway** في Coolify أنشئ رمزًا خاصًا بجهاز هذا الشخص:

```bash
python -m relay enroll-code --minutes 10
```

أعطه الرمز على نحو خاص. يفتح ورق على جهازه ثم «الإعدادات ← الوصول من الهاتف · الإنترنت»، ويدخل `https://waraqstudio.jadallah.work` واسم جهازه والرمز. بعد ظهور «متصل» ينشئ QR ويقرأه بهاتفه، ويطابق الرقم ويوافق من الكمبيوتر.

كرر برمز جديد لكل جهاز. لا تعِد استخدام الرمز ولا تنسخ ملف هوية جهاز إلى آخر. لا يحتاج الأشخاص إلى دخول Coolify؛ تظل إدارة الخادم ورموز التسجيل بيدك. لا توجد حسابات مستخدمين مستقلة في البوابة؛ صلاحية الهاتف هي الاقتران الذي وافق عليه الكمبيوتر.

لكل جهاز هاتف واحد. ربط هاتف بديل يتطلب إلغاء الهاتف الحالي من ورق ثم إنشاء QR جديد. متصفح مختلف على الهاتف نفسه يعد جلسة مختلفة؛ استخدم المتصفح المقترن أو ألغ الاقتران السابق أولًا. تنتهي الجلسة بعد 30 يومًا أو خمول سبعة أيام، وعندها يمكن الاقتران من جديد بموافقة الكمبيوتر.

## 7. اختبر قبل الاستخدام اليومي

جرّب الهاتف عبر بيانات الجوال، مع ورق مفتوح والكمبيوتر مستيقظًا. سجل جهازين واقرن هاتفًا مستقلًا بكل منهما؛ يجب أن يرى كل هاتف جهازه فقط. حاول ربط هاتف ثانٍ بالجهاز الأول: يجب رفضه حتى إلغاء الأول. اختبر الرفع والتنزيل، ثم أوقف الجهاز الأول وتأكد أن الثاني يبقى مستقلًا.

احتفظ بنسخ PostgreSQL الاحتياطية خارج VPS. تعليمات النسخ والاستعادة والتشخيص وحدود النقل موجودة في [الدليل الكامل](README_AR.md). يضيف مسار GitHub Actions فحص Docker Compose مع PostgreSQL على Ubuntu، ويشترط نشر الإصدار نجاحه؛ لم يُشغّل Docker محليًا هنا، فراجع نتيجة التشغيل للالتزام المختار. تظل تجربة الدومين وCoolify والهاتف الخارجي أعلاه مطلوبة في بيئتك.
