# إصلاح خمول المحرك ووضوح مركز العمليات

## المشكلة والحدود

كان تحديث الحسابات التلقائي يطلب تشغيل المحرك كل خمس ثوانٍ، متجاوزًا مهلة إعادة المحاولة. كان بدء التشغيل يعيد تجزئة حزمة المحرك كاملة قبل اكتشاف رابط كاش Windows `Content.IE5` ورفضه. أعاد التحقيق إنتاج استهلاك 12.43% من معالج جهاز ذي 12 معالجًا منطقيًا أثناء الخمول. قياس التحقيق القديم يخص عملية Python؛ قياسات القبول الجديدة تفصلها عن مجموع شجرة عمليات المحرك.

الإصلاح يبقي المحرك جاهزًا عند فتح التطبيق إذا كانت الحسابات مفعّلة. لا يغيّر قاعدة المهام، أو بنية الإعدادات، أو بيانات اعتماد الحسابات، أو سياسات توزيع المهام وإعادة تنفيذها. يظل رفض الروابط غير الآمنة، وفحص الحزمة المثبتة، والتحقق من ملكية العمليات والجلسات إلزاميًا.

## التهيئة الآمنة والمزامنة

- يُقفل ملف التشغيل وتُفحص مجلداته قبل فحص الحزمة. يُقبل فقط Junction كاش Windows المحدد إلى `IE` المجاور، داخل المساحة الخاصة نفسها، ويُفحص عبر مقبض لا يتبع الرابط. لا يجتاز المسح الرابط ولا يغيّر ACL عبره، ويؤمّن مجلد `IE` عبر مساره الحقيقي.
- تبقى الروابط الأخرى والأهداف الخارجية والمفقودة والدائرية مرفوضة. تثبّت مقابض المسارات أثناء المراجعة لمنع تبديلها، وتُطبّق الصلاحيات إلى الكائن المفتوح نفسه.
- يتشارك مؤقت الواجهة والمجدول بوابة تفعيل وانتظار وطلب واحد في الخدمة. يجري الانتظار التصاعدي للأعطال المؤقتة حتى 60 ثانية؛ أخطاء الحماية والملكية وسلامة الحزمة توقف الاسترداد التلقائي حتى الفحص اليدوي أو إعادة فتح التطبيق.
- لا يتجاوز `force` انتظار الخطأ أو تعطيل الحسابات؛ يطلب حداثة البيانات فقط. يستمر فحص الجلسات السابقة قبل السماح بالمحاولة اليدوية.
- لا تُكرر عمليات الإنشاء والتعديل أو الأخطاء الثابتة تلقائيًا. تبقى إعادة القراءة الآمنة المحدودة خاصة بأخطاء النقل المؤقتة.
- تعرض `accountEngine` حقولًا إضافية منقحة: `reasonCode` و`nextRetryAt` و`requiresManualRecovery`. تُحجب الأخطاء الخام والمسارات وبيانات الاعتماد عن QML والهاتف.
- لا تُكتب نسخة الكاش العامة عند تطابق بياناتها. تُبلغ الواجهة بتغير الانشغال حتى إذا ظلت صفوف الحسابات متطابقة.
- يصبح إعداد المحرك والتحقق من الحزمة قابلين للإلغاء أثناء الإغلاق؛ لا تُترك عمليات ابن أو خيوط فحص اختبارية معلقة.

## كلفة تحديث الواجهة

يبقى مؤقت العرض 700ms. تستخدم قراءة المهام علامة داخلية من `total_changes` و`PRAGMA data_version` تحت قفل اتصال SQLite نفسه. عند ثبات القاعدة يُعاد استخدام الإسقاط العام الحالي؛ لا تُحتفظ بنسخة أخرى من إعدادات جميع المهام. تظل تغييرات العمال والسجل والإغلاق التلقائي حية، وتُحدّث تسميات المحاولات عند حلول الموعد أو تغير اليوم أو رجوع ساعة النظام.

## الخط وشارات المراحل

أصبح وزن النصوص `Font.Bold` (700) مركزيًا، مع Segoe UI، مع إبقاء Consolas لمحرر JSON واستخدام Bold فيه أيضًا. بقيت أحجام الخطوط ونطاق التكبير والكثافة كما هي.

أصبحت شارات التنزيل تركوازية، والتفريغ زرقاء، وملف Word ذهبية. لكل شارة اسم وأيقونة وحالة نصية ورمز حالة، ويظهر الخطر بالأحمر. مصدرها `row.steps` الفعلي؛ مهمة TXT لا تحصل على مراحل وهمية. يظهر عمود المراحل في العرض الواسع، وتنتقل الشارات نفسها إلى سطر ملتف تحت عنوان المهمة عند ضيق المحتوى. لا تضيف الشارات مؤقتات أو حركة مستمرة أو إجراءات خلفية.

عند قصر مساحة مركز العمليات تصبح بطاقات الإحصاءات في سطر واحد وتقل المسافات الرأسية فقط. اجتاز المقاس1060×720 مع تكبير140% اختبار ظهور صف المهمة الأول كاملًا، بما فيه العنوان والمراحل والتقدم والحالة والتحديد وزر التفاصيل، في الثيمين والكثافتين وحالتي القائمة؛ لا تصغّر هذه المعالجة الخط ولا تخفي إجراءً.

## التحقق وإعادة إنتاج القياسات

تغطي اختبارات الوحدات الروابط الفعلية، وتبديل المسارات، والصلاحيات، وإلغاء البدء، وملكية العملية، وبوابة المزامنة، والانتظار، والفحص اليدوي، والكاش، وكتابة SQLite من الاتصال نفسه أو اتصال آخر، ومواعيد المحاولات.

```powershell
python -m pytest tests -q
python tests/verify_idle.py
python tests/verify_embedded_engine.py
python tests/verify_ui.py
python tests/verify_redesign.py output/idle-fix/ui
python tests/verify_stage_badges.py
```

يستخدم فحص الخمول قواعد ومجلدات حسابات فارغة مؤقتة، دون OAuth أو طلبات معالجة مدفوعة. يثبت ثبات عدد فحوص الحزمة وقراءات الطابور أثناء الخمول، وعدم إعادة كتابة الكاش، وتعافي ملف ذي رابط مرفوض بعد الفحص اليدوي، ونجاح فتح الملف نفسه ثلاث مرات. تحفظ جميع المقاييس تحت `output/idle-fix/` محليًا. تنفذه CI وRelease أيضًا، ويفتح فحص الحزمة النظيفة الملف نفسه مرتين للتأكد من عدم عودة مشكلة روابط Windows بعد التشغيل الأول.

```powershell
python tests/verify_idle.py --case healthy --jobs 0 --warmup 30 --measure 120 --performance --evidence output/idle-fix/performance
python tests/verify_idle.py --case healthy --jobs 18 --warmup 30 --measure 120 --performance --evidence output/idle-fix/performance
python tests/verify_idle.py --case healthy --jobs 5000 --warmup 30 --measure 300 --performance --evidence output/idle-fix/performance
```

تشمل أرقام CPU والذاكرة مجموع شجرة العمليات، مع حقول منفصلة لعملية الواجهة. عداد قراءات I/O لا يساوي بالضرورة حركة القرص الفعلية بسبب كاش Windows. لا تقارن ذاكرة شجرة المحرك كلها بذاكرة عملية الواجهة وحدها.

لا تستبدل اختبارات الأداء حواجز الأمان الحتمية: يبقى فحص الحزمة كاملًا قبل كل تشغيل فعلي جديد، ولا تتوقف اختبارات موجودة لمجرد تغير العرض.

## نتائج القبول المحلية

- الاختبارات الآلية: **459 نجح، واختبار واحد متجاوز** بسبب عدم توفر امتياز إنشاء symlink في Windows؛ اختبارات Junction الفعلية والصلاحيات والاستبدال والإلغاء نجحت. يتحقق اختبار منع سرد رابط الكاش من DACL نفسه ويحافظ عليه، سواء سمحت امتيازات حساب Windows بفتح مقبض الفحص الأوسع أو منعته، ويغلق المقبض في الحالتين.
- مصفوفة الواجهة: **432 حالة صفحة و60 حالة نافذة**، بالإضافة إلى **162 حالة للشارات**، دون رسائل QML. اجتازت فحوص OAuth الاختبارية، وإلغاء الدخول المتزامن، واختيار الطريقة أثناء المزامنة، واستمرار RPC التنفيذ أثناء انتظار الحصة.
- نجح فحص المحرك الأصلي ببيانات DPAPI اصطناعية، وحدود التزامن، والجلسات الأبناء، والاحتفاظ بالدخول بعد إعادة الفتح، دون OAuth حقيقي أو معالجة مدفوعة.
- نجح فحص الخمول وإصلاح الرابط المرفوض يدويًا وإعادة فتح الملف نفسه ثلاث مرات، مع DACL يحاكي منع Windows لقائمة محتويات رابط الكاش. لم تتغير صلاحيات الرابط أو هدفه الخارجي الاختباري.
- نجح بناء Windows وفحصه مع PATH محدود بـSystem32 وملف مستخدم جديد، ثم أعيد فتح ملف المحرك نفسه في الحزمة. موارد QML في الحزمة مطابقة للمصدر النهائي.
- نجحت فحوص واجهة الهاتف، وTLS/Internet الفعلي المحلي، وPWA، والتصفية والحذف والتصدير والتكبير، وتمرير قوائم100 و500 و2000 مهمة.

قياس Windows ذي12 معالجًا منطقيًا، بالرسم الافتراضي، بعد30 ثانية إحماء:

| المهام | مدة الخمول | CPU الواجهة | CPU شجرة العمليات | RAM الواجهة عند النهاية | إعادة فحص الحزمة/الطابور أثناء القياس |
|---:|---:|---:|---:|---:|---|
|0|120 ثانية|0.178%|0.282%|311.75 MB|صفر/صفر|
|18|120 ثانية|0.162%|0.272%|303.91 MB|صفر/صفر|
|5000|300 ثانية|0.180%|0.250%|373.05 MB|صفر/صفر|

هذه عينات على جهاز العمل، وليست ضمانًا لرقم واحد على جميع الأجهزة. مقارنة0.162% للواجهة بحالة التحقيق المعاد إنتاجها12.43% تعني انخفاضًا يقارب98.7% على الجهاز نفسه، مع مراعاة اختلاف السيناريو والزمن. لم يُعد حفظ الكاش في فترات الخمول المقاسة، وبقيت تغييرات الحالة قابلة للوصول.

في عينة5000 مهمة انخفض Working Set لشجرة العمليات42.87 MB خلال الخمس دقائق، فاجتازت حد عدم النمو المستمر. قراءة I/O خلال القياس0.024 MB، مقابل مئات الميجابايت في نافذة قصيرة من الحالة المعيبة؛ لا تعني هذه المقارنة أن كل قراءات الحالة السابقة وصلت إلى القرص الفعلي.
